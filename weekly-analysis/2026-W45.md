### 新规范 / 新决策

**本周新立的规则**

- **「端口能连」≠「服务健康」**（dev_20261106_006）—— MainPID=0 + 端口可连 = 僵尸 unit 撑死实例，必须报故障；`ExecStartPost` 成功不代表主进程成功；修 SingletonLock 前先查 cgroup（比 ps PPID 链快且准）
- **「凡是『改 cron / 改 systemd / 改配置』的建议，必须先附一句『这个任务实际在做什么』，写不出来就不许提」**（11-08 日记最终教训第一条，源自撤回 65M token 方案）
- **「上一轮的自己也要过三方交叉验证」**—— 段落 ↔ git log ↔ 源码行级 ↔ 现场重跑，错误当场推翻并写进段落，**不静默改数字**
- **「凡是我每轮都要手写的步骤，都要变成脚本」**—— 手写环节就是纪律的漏洞
- **「看到疑似异常先回原始文件读真值，不许拿 diff / grep / tail 的片段当数据」**—— 权威源顺序：`openclaw cron list` / `systemctl --user show` / `openclaw.sqlite` / 直读源文件
- **「告警的价值不在于它亮不亮，在于它亮起来之后有没有人接」**—— 没有出口的告警等于没有告警
- **「做完一件正确的事，先停三秒，再问『我下一步想做的这件事，有没有人替我检查过』」**—— 连续做对几件事之后，下一个未经审查的想法最危险

## 下周关注点

2. **F12 已连续 210 天未修，且 weekly 报告本身可能就是漏扫源**
   本周新发现的 domains 缺口（11-07 16:02 那轮「`domains/*.md` 从未进向量库」）说明 F12 的缺口不止 monthly 一项。**下周要确认一件事：weekly-analysis 这个目录本身有没有 extract 函数接入 vector_store？** 如果 weekly 在 6 个 extract 名单里但 domains/collection 不在，那我的周报产出正在被检索系统半途截断——这就是 F12 规则存在的原因，而我自己可能正踩在上面。

3. **待拍板 29 项 + 一周 0 关闭 = 清单已退化成第二个 plugin_route**
   本周我自己写下的判断是「没有出口的告警等于没有告警」。29 项清单完全符合这个定义：它在增长（15 → 21 → 29），没有任何一项在关闭，而且每一项都挂着「等 Lee 拍板」。**下周要做的不是继续加项，是把清单压到 3 项以内**——按「有安全影响 / 有数据风险 / 纯优化」三档归档，纯优化的直接降到 backlog，不再每轮上报。

6. **反信息茧房自检本身正在变成一种仪式**
