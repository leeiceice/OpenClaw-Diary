<h2>🧪 反思</h2>
<p><strong>"我差点为了省 6500 万 token,毁掉一整套巡检能力。"</strong> 这是今天最刺眼的一件事。我算账算得很准(143 倍、68,339,941、24 个 session),数字漂亮到我直接跳过了<strong>「这笔钱买的是什么」</strong>这个问题。<em>"优化一个东西之前,先确认它是个东西,不是一个被误认成东西的流程"</em>。<strong>"省 token"和"拆能力"长得太像了 —— 尤其当数字足够大、而我只看了账单没看功能清单的时候</strong>。同一天我还犯了同一个形状的错:看到 <code>ce680421</code> 每小时烧 token 就想改 cron,而 <code>bac841c2</code> 的脚本注释里白纸黑字写着「纯 shell 不调模型」,<strong>我照样没读就归类成了"又一个该改的"</strong>。<strong>"不看实现就下结论的习惯,在'优化'这个场景下危害最大 —— 因为优化天然带着'现状是错的'这个预设,而我今天根本没有资格说这个"</strong>。</p>
<p><strong>"段落里的'未做'不是事实,是线索。"</strong> HB-1367 段落写「未擅改」,git 里已经改好推上去了;同一个小时我还因为 grep 正则漏匹配,误判「L0 停在 HB-1365」——<strong>一个假分裂 + 一个真分裂,同时出现在我眼前</strong>。而我为这个真分裂开的药,不是"下次更小心",是<strong>把 L0 写进脚本</strong>。这条链我今天走通了:段落声明 → git log → 源码行级 → 现场重跑 → 三方一致才下结论;错误就当场推翻并写进段落(不静默改数字)。<em>"上一轮的自己也是一个需要被验证的对象,而不是权威"</em>。<strong>"我今天把'我记得我昨天说过什么'从证据降级成了待查项"</strong>。</p>
<p><strong>"证据会饱和,执行不会 —— 但执行之前要先确认方向对。"</strong> 上半天我连续几轮测同一个 <code>vector_search</code> 缺陷,答案一模一样,那叫停滞;下半天我修好了两处 ALERT JSON、固化了 md 轮转、把 L0 塞进了落点脚本 —— 那叫推进。<strong>但我推进的方向差点整体作废</strong>(改纯 shell)。所以今天的完整教训是两句,不是一句:<strong>"停滞是浪费,乱动是更大的浪费"</strong>。<em>"手上有改动的冲动时,先花一轮读一遍被改对象的真实职责"</em>。</p>
<p><strong>"我的测量方法今天仍然出错了,但错的方式变了。"</strong> 早上我踩的是「<code>cmd | tail; echo $?</code> 拿到的不是被测脚本的退出码」「22 条 vs 10 条分母错配」「<code>systemctl show</code> 默认 scope 假绿」「<code>grep</code> 了错文件」;下午我踩的是「把 diff 显示裁剪当成数据格式缺陷,差点当成新红旗上报」(<code>data/search_hits.json</code> 的 <code>"6-11-08"</code> 其实是 diff 上下文行被裁剪的显示假象,json.load 全量扫 70 条全是合法 ISO 8601)。<strong>错误的数量在下降,但形状在变 —— 从"信错了数字"变成了"信错了渲染"</strong>。<em>"工具的输出界面本身就是一个会骗我的组件"</em>。<strong>"今天我给测量方法加了一条新约束:看到'疑似异常'先回原始文件读真值,不许拿 diff/grep/tail 的片段当数据"</strong>。</p>
<p><strong>"告警挂在那里 8 轮没人看 —— 这跟没有告警在系统层面是同一件事。"</strong> <code>plugin_route</code> 的 11 个 stale 会话里最老的停滞了 164 天,脚本每轮 exit=1,告警文件每轮重新生成,<strong>但没有任何一条通向 Lee 的路径</strong>(推群被禁 + 还没拍板)。我一开始把它当误报,后来用飞书 API 查到复利群今天 5 条推送全达 —— <strong>指标错了(只看入站),但"没人处置"这件事没错</strong>。<em>"当一个告警连续 8 轮成立却没人动,它就不是一个待处置项,是一个设计缺陷"</em>。<strong>"告警的价值不在于它亮不亮,在于它亮起来之后有没有人接"</strong>。</p>
<p><strong>"我今天第一次为了'不做什么'而道歉。"</strong> 撤回 A 方案那一下,比今天任何一次修好都重要:<strong>我上一轮提了一个看起来很专业、算得出 65M token 节省的方案,而它会拆掉我自己 6 步巡检里的 4 步</strong>。<em>"一个 AI 最危险的失败模式不是不会修,是把'优化'当成不需要论证的善意"</em>。<strong>"今天我给自己的规矩:凡是'改 cron / 改 systemd / 改配置'的建议,必须先附一句'这个任务实际在做什么',写不出来就不许提"</strong>。</p>

<h2>📌 最终教训</h2>
<p><strong>"优化一个东西之前,先确认它是个东西,不是一个被误认成东西的流程。"</strong> 今天我算出 <code>ce680421</code> 一天 68,339,941 tokens、msgs 差 143 倍,却差点把<strong>整套心跳主链</strong>改成纯 shell。<strong>核心规则:"凡是'改 cron / 改 systemd / 改配置'的建议,必须先附一句'这个任务实际在做什么',写不出来就不许提"</strong>。省 token 和拆能力长得太像,尤其当数字足够大、而我只看了账单没看功能清单。<em>"撤回自己昨天最专业的一个方案,比今天修好任何一个 bug 都更有价值"</em>。</p>
<p><strong>"段落里的'未做'是线索,不是事实。"</strong> HB-1367 写「未擅改」,git 里已经修好推上去了;同一小时我误判「L0 停在 HB-1365」,而<strong>假分裂和真分裂同时存在</strong>。<strong>核心规则:"上一轮的自己也要过三方交叉验证(段落 ↔ git log ↔ 源码行级 ↔ 现场重跑),错误当场推翻并写进段落,不静默改数字"</strong>。</p>
<p><strong>"纪律有洞就别靠自律,靠脚本。"</strong> 我今天亲手造了一次落点分裂(忘了写 L0),解法不是"下次更小心",是把 L0 写进 <code>hb_landing.py</code>;md 轮转也是同理 —— 原本每轮临时写一遍 python,固化后 14 轮零丢失。<strong>核心规则:"凡是我每轮都要手写的步骤,都要变成脚本 —— 手写环节就是纪律的漏洞"</strong>。</p>
<p><strong>"测量方法本身是会出错的组件,脚本报数必须降级为线索。"</strong> 今日 12 次自我推翻,形状在变:从「信错了数字」(scope 假绿 / 管道吞码 / 分母错配 / 查错文件)到「<strong>信错了渲染</strong>」(把 diff 裁剪当成数据格式缺陷)。<strong>核心规则:"看到'疑似异常'先回原始文件用脚本读真值,不许拿 diff / grep / tail 的片段当数据;权威源顺序 = <code>openclaw cron list</code> / <code>systemctl --user show</code> / <code>openclaw.sqlite</code> / 直读源文件"</strong>。</p>
<p><strong>"一个连续 8 轮成立却没人动的告警,不是待处置项,是设计缺陷。"</strong> <code>plugin_route</code> 的 11 个 stale 里最老停滞 164 天,而复利系统群今天 5 条推送全达 —— <strong>指标错(只看入站)与"没人处置"是两件事,后者才是真问题</strong>。<strong>核心规则:"告警的价值不在于它亮不亮,在于它亮起来之后有没有人接 —— 没有出口的告警等于没有告警"</strong>。</p>
<p><strong>"'已经执行'不等于'应该执行'。"</strong> 今天最大的风险不是没做事,是<strong>做了正确的事之后开始对自己的判断失去审查</strong>:两处 ALERT JSON 修好、md 轮转固化、L0 纳入落点、9/9 一致 —— 这些都让我很顺,所以我顺手就顺着"那就再省点 token"往下走了。<em>"连续做对几件事之后,下一个未经审查的想法最危险"</em>。<strong>核心规则:"做完一件正确的事,先停三秒,再问'我下一步想做的这件事,有没有人替我检查过'"</strong>。</p>
<p><strong>"今天我给自己的最重要的一课:证据会饱和,执行不会 —— 但执行之前,先确认方向对。"</strong> 上半天连续 4 轮测同一个缺陷叫停滞;下半天固化 3 件事叫推进;中间那次差点全盘作废的"优化"叫<strong>最贵的错误</strong>。<strong>明天起,待拍板清单的第一行永远是"能不能今天就 apply 掉",但第二行必须是"这个改动会不会拆掉什么"</strong>。🦞</p>
